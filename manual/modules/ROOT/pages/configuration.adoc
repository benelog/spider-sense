= Configuration
:navtitle: Configuration

Every option of Spider Sense is a `spidersense.*` key.
You set a key as a system property on the command line of the JVM that runs the application, or as a line of a properties file.
The standalone jar also takes it as a `--key=value` argument.
The sources in order of precedence, highest first, are the `--key=value` argument, the `-Dspidersense.key` system property, the environment variable of the same name, the properties file, and the default.
The environment variable of a key is its name in upper case with every `.` and `-` made `_`, so `spidersense.slow.query.ms` is `SPIDERSENSE_SLOW_QUERY_MS`.
An environment variable that is set but empty counts as unset, so it hides neither the properties file nor the default.
A numeric key whose value is not a number, such as `spidersense.slow.query.ms=1x`, is a warning on stderr, and that key alone takes its default; every other key keeps its value.
The launcher's own arguments are the exception: the standalone jar answers a numeric `--key=value` argument that is not a number, such as `--slow.query.ms=1x` or `--retention.spans=1x`, as a usage error, printing `spider-sense: --slow.query.ms is not a number: 1x` on stderr and exiting `2` without starting.

[#properties]
== Properties

[cols="2,1,3",options="header"]
|===
| Property | Default | Meaning

| `spidersense.port`
| `4000`
| The UI and OTLP/HTTP port.

| `spidersense.host`
| `127.0.0.1`
| The bind address. Use `0.0.0.0` to reach it from another machine, which also accepts a request under any host name (xref:api.adoc#conventions[API conventions]).

| `spidersense.collector`
| unset
| Agent mode: forward to this base URL instead of starting the embedded UI. See xref:modes.adoc#forwarding[forwarding].

| `spidersense.service`
| unset
| Agent mode: the default of `otel.service.name`. When both are set, `otel.service.name` names the service, for the exporter and for the embedded Spider Sense alike.

| `spidersense.db`
| `~/db/spider-sense/sense`
| The H2 database path, or a `jdbc:h2:` URL. `AUTO_SERVER=TRUE` is appended to a path. See xref:storage.adoc[Storage].

| `spidersense.retention.hours`
| `24`
| Rows older than this are deleted by the sweeper.

| `spidersense.retention.spans`
| `1000000`
| The most `span` rows kept. The sweeper deletes the oldest hour of everything until the count is under it, and `0` means no cap. See xref:storage.adoc#retention[Retention].

| `spidersense.ingest.max-spans-per-second`
| unset
| Above this many spans in one second the receiver drops the spans of traces it has not seen yet, and counts them on `/api/status`. See xref:storage.adoc#ingest-cap[the ingest cap].

| `spidersense.slow.request.ms`
| `500`
| A server span slower than this is a tingle. It is also the Apdex scale.

| `spidersense.slow.query.ms`
| `100`
| A database span slower than this is a tingle, and the one the extension captures a stack trace for and reads the index catalog for.

| `spidersense.open`
| `false`
| Agent mode: open the browser at startup (`java.awt.Desktop`), best effort.

| `spidersense.app.packages`
| unset
| Comma-separated package prefixes that count as application code in a finding's `code` frames. Unset means everything that is not a known framework. See xref:findings.adoc#code[the code frames].

| `spidersense.ignore.endpoints`
| `/actuator/**,/health,/healthz,/livez,/readyz`
| Comma-separated glob patterns. An entry span whose endpoint matches one of them is not a request. An empty value ignores nothing. See <<ignored-endpoints,Ignored endpoints>>.

| `spidersense.source.dirs`
| `src/main/java` and `src/main/kotlin` of the working directory and of each of its immediate subdirectories
| Comma-separated source roots, relative ones against the working directory. A code frame resolves to the first file under them that matches its package and file name, which gives the UI its source lines and editor links and the CLI its suspect-change line. An empty value names no root and turns all three off. See <<source-dirs,Source roots>>.
|===

=== On the command line

In agent mode the properties go on the same command line as `-javaagent:`, before `-jar`:

[source,bash]
----
java -javaagent:"$SENSE" -Dspidersense.port=4001 -Dspidersense.slow.query.ms=50 -jar app.jar
----

The standalone jar accepts both forms, and `--key=value` is the shorter one:

[source,bash]
----
java -jar "$SENSE" --port=4001 --host=0.0.0.0
----

From a build tool, the `spiderSense { }` block of xref:gradle-plugin.adoc#block[the Gradle plugin] has a line for every property in the table, and xref:maven.adoc[Maven] passes them as JVM arguments.

[#properties-file]
=== In a properties file

The same keys go in a properties file, one per line, so the command line carries only `-javaagent`:

.spider-sense.properties
[source,properties]
----
spidersense.port=4001
spidersense.service=orders
spidersense.slow.query.ms=50
spidersense.ignore.endpoints=/actuator/**,/internal/**
----

[source,bash]
----
java -javaagent:"$SENSE" -jar app.jar
----

Spider Sense reads `spider-sense.properties` from the working directory of the JVM, when that file exists.
`-Dspidersense.config=<path>`, or the environment variable `SPIDERSENSE_CONFIG`, names another file.
A named file that does not exist is a warning on stderr, and the application starts without it.
The launcher names the file it read on stdout.

The launcher reads the file first, in `premain`, in the standalone `main`, and before it runs a CLI command.
It applies every `spidersense.*` key of the file as the system property of the same name, unless that property or its environment variable is already set.
From then on the launcher, the server, the extension and the CLI read the system properties exactly as they do for `-D`, so the file adds no second reader anywhere.
A key given as a system property, or as an environment variable of the same name, therefore wins over the file.
A value is trimmed, and an empty value counts: `spidersense.ignore.endpoints=` ignores nothing, as it does on the command line.
Keys without the `spidersense.` prefix are left alone, so the same file can be handed to the OpenTelemetry agent with `-Dotel.javaagent.configuration-file=spider-sense.properties` and then carry `otel.*` keys as well.
A `spidersense.*` key that is not in the table is applied with a warning, so a typo is visible.

The file is read in every mode: under `-javaagent`, by the standalone jar, and by the xref:cli.adoc[CLI].
The CLI's default `--url` is then the Spider Sense that the file's `spidersense.collector`, or `spidersense.host` and `spidersense.port` with the defaults filled in, point to.
A command run from the project's directory therefore asks the Spider Sense that directory's file points at.
The environment variable `SPIDERSENSE_URL` still wins over what the file implies.
Under xref:gradle-plugin.adoc[the Gradle plugin] or xref:maven.adoc[Maven] the file is read as well, because the working directory of the forked JVM is the project's.
A `-D` property that the build tool adds wins over the file.
The Gradle plugin's `configFile` names another file, as `-Dspidersense.config` does.

=== Environment variables

Every key has the environment variable described at the top of this page.
Two thresholds are also read from the environment by the OpenTelemetry agent extension itself, because the extension that captures stack traces is configured before the server is:

[cols="1,2",options="header"]
|===
| Variable | Equivalent property

| `SPIDERSENSE_SLOW_QUERY_MS`
| `spidersense.slow.query.ms`

| `SPIDERSENSE_SLOW_REQUEST_MS`
| `spidersense.slow.request.ms`
|===

Both are read once, when the extension is built.

== OpenTelemetry properties

Every `otel.*` system property and `OTEL_*` environment variable of the OpenTelemetry Java agent still works as that agent documents it.
Spider Sense only fills in defaults, and only where you have set neither the property nor its environment variable.

.What Spider Sense sets for the OpenTelemetry agent, unless you set it
[cols="2,2,3",options="header"]
|===
| Property | Value | Why

| `otel.exporter.otlp.protocol`
| `http/protobuf`
| There is no gRPC receiver.

| `otel.exporter.otlp.endpoint`
| `http://127.0.0.1:<port>`, or `spidersense.collector` when that is set
| The literal address rather than `localhost`, which may resolve to `::1` while the UI binds `127.0.0.1`.

| `otel.service.name`
| `spidersense.service` when given, otherwise the agent's own default `unknown_service:java`
| The UI shows the jar or main class hint from the resource attributes when the name is the default.

| `otel.bsp.schedule.delay`, `otel.blrp.schedule.delay`
| `1000`
| A local tool should show a request within a second or two.

| `otel.metric.export.interval`
| `5000`
| The same reason, for metrics.

| `otel.metrics.exporter`, `otel.logs.exporter`, `otel.traces.exporter`
| `otlp`, or `none` when the port is held by something that is not a Spider Sense
| All three signals go to the collector, and none goes to a port held by something else, where every export would fail (xref:modes.adoc[The Three Modes]).

| `otel.javaagent.exclude-class-loaders`
| Spider Sense's own server class loader, appended to a list you set
| The agent skips every class the UI server defines, so the UI's own requests never become spans.

| `otel.instrumentation.runtime-telemetry.enabled`
| `true`
| The JVM metrics behind the xref:pages.adoc#jvm[JVM page]. This is already the agent's default.

| `otel.javaagent.extensions`
| The extension jar Spider Sense extracted, appended to a list you set
| The extension records `code.stacktrace` on a slow query, on the fifth repeat of an N+1, and on a slow outbound call. It also reads the index catalog of the tables a slow statement touches, which is a finding's xref:findings.adoc#schema[schema block].
|===

Beyond this table, Spider Sense sets in the application's JVM only the `spidersense.*` keys of <<properties-file,the properties file>>, each as the system property of the same name, and no other system property.
Its own server logs at `warn` through a `simplelogger.properties` only its class loader sees, so an application that logs through slf4j-simple keeps its own level, and `-Dorg.slf4j.simpleLogger.defaultLogLevel=` still raises the server's.

Always set `-Dotel.service.name=`, because without it the service is `unknown_service:java` and the service filter has nothing to select.
`-Dspidersense.service=` does the same thing in agent mode.

[#ignored-endpoints]
== Ignored endpoints

`spidersense.ignore.endpoints` is a comma-separated list of glob patterns.
An entry span whose endpoint matches one of them is written with `entry` false, exactly as a root `INTERNAL` span is (xref:design.adoc#endpoint-identity[Endpoint identity]).
It is stored, is in its trace and is in the trace list, but it is not an endpoint, not a request, not in the Apdex, never a slow-request tingle, never a finding and never a `check` verdict.

A health check polled every few seconds is the most frequent request of a typical Spring Boot application and the least interesting one.
It is fast, it never fails, and it dilutes the request count, the Apdex, `check` and every `slow-endpoint` judgement.
The default is `/actuator/**,/health,/healthz,/livez,/readyz`, and an empty value ignores nothing:

[source,bash]
----
java -javaagent:"$SENSE" -Dspidersense.ignore.endpoints= -jar app.jar
----

A pattern is matched against the endpoint name as xref:design.adoc#endpoint-identity[Endpoint identity] defines it, which is `GET /actuator/health` when the framework reports a route, and the span name when it does not.

* A pattern that starts with `/` is matched against the name with its leading `METHOD ` removed, so `/actuator/**` covers every method.
* A pattern with a method, such as `GET /actuator/**`, is matched against the whole name.
* When neither matches and the span carries `url.path`, the same patterns are tried against `METHOD url.path` and against `url.path`, so a framework that reports no route is still covered.

`**` matches anything including `/`, `*` matches anything but `/`, and `?` matches one character that is not `/`.
The match is case-sensitive and covers the whole name.
`/api/status` shows the list in force as `ignore.endpoints`, and so does the text rendering of the `status` command.

[#source-dirs]
== Source roots

Spider Sense runs where the source is, so it can show the lines a code frame points at.
A frame `orders.OrderService.load(OrderService.java:41)` resolves to the first `<root>/orders/OrderService.java` that exists under the roots of `spidersense.source.dirs`.

The default covers a single-module build and a multi-module one: `src/main/java` and `src/main/kotlin` of the working directory, then the same two under each of its immediate subdirectories.
Under the Gradle plugin, Maven or `java -jar` from the project directory, the working directory is the project's, so the default usually fits.
Name the roots when the sources live elsewhere, or deeper:

[source,bash]
----
java -javaagent:"$SENSE" -Dspidersense.source.dirs=services/orders/src/main/java,shared/src/main/java -jar app.jar
----

A root that does not exist is left out.
A frame without a file and a line, such as `Unknown Source`, does not resolve.
Neither does a frame whose path would leave its root: only dotted Java identifiers and a plain file name with a `.java`, `.kt`, `.groovy` or `.scala` extension make a path, and the file, symbolic links followed, must lie under its root.
The CLI reads the same property, as `-Dspidersense.source.dirs` before `-jar` or from `spider-sense.properties`, to find a frame's file for its xref:cli.adoc#suspect-change[suspect-change line].

== How to send data

Data reaches the collector in three ways.
The UI's "How to send data" dialog prints all three with the port actually in use.

A JVM under the OpenTelemetry Java agent that Spider Sense carries:

[source,bash]
----
java -javaagent:"$SENSE" -Dotel.service.name=my-app -jar app.jar
----

Any OpenTelemetry SDK, pointed at a standalone Spider Sense (xref:modes.adoc#other-languages[Python, Node.js and Go]):

[source,bash]
----
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4000
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
----

The same two variables point a Java application under the stock OpenTelemetry Java agent, or any compatible agent, at it:

[source,bash]
----
OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4000 OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf \
    java -javaagent:opentelemetry-javaagent.jar -Dotel.service.name=my-app -jar app.jar
----

It lacks the defaults and the extension the Spider Sense jar adds, as xref:modes.adoc#standalone[Standalone] describes.

Anything that can post JSON, over OTLP/JSON:

[source,bash]
----
curl -X POST http://127.0.0.1:4000/v1/traces \
     -H 'Content-Type: application/json' \
     -d @spans.json
----

`/v1/traces`, `/v1/metrics` and `/v1/logs` accept `application/x-protobuf` and `application/json`, with `Content-Encoding: gzip`.
xref:api.adoc#ingest[The HTTP API] describes what each one answers.
