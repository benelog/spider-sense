= Installation
:navtitle: Installation

Spider Sense requires Java 21 or later.
It is one jar, and that jar carries the OpenTelemetry Java agent, the collector, the UI and the command line.
Nothing else has to be installed: no Docker, no account, and no server to run.

[#coordinates]
== Coordinates

Releases are published to https://central.sonatype.com/namespace/net.benelog.spidersense[Maven Central], so a build needs no repository beyond the default one.
The current version is `{project-version}`.

[cols="1,2,2",options="header"]
|===
| Artifact | Coordinates | What it is

| The jar
| `{project-group}:spider-sense:{project-version}`
| The single distributable jar, built by `:spider-sense-agent:senseJar`. Its POM declares no dependencies.

| The Gradle plugin
| `{project-group}:spider-sense-gradle-plugin:{project-version}`, marker `{project-group}:net.benelog.spidersense.gradle.plugin`
| The plugin id `net.benelog.spidersense`, which puts `-javaagent` on `bootRun` and `run`. See xref:gradle-plugin.adoc[The Gradle Plugin].
|===

The jar and the plugin are released together at one version, which is `version` in the root `gradle.properties` of the repository.
By default the plugin resolves the jar at that same version, so a plugin and the jar it fetches are always the same release.
The repository publishes both with `./gradlew publishToMavenLocal` into `~/.m2`, and, signed, with `./gradlew centralBundle` into one bundle for the Central Portal, as `RELEASING.md` in the repository describes.
The Gradle Plugin Portal proxies Maven Central, so the default `pluginManagement` finds the plugin.

NOTE: This manual describes `main`, which is ahead of the latest release, so a feature it documents may not be in `{project-version}` yet.
Build the jar from a checkout to have everything it describes.

[#from-source]
== From a checkout

[source,bash,subs="attributes+"]
----
git clone https://github.com/{project-repo}.git
cd spider-sense
./gradlew :spider-sense-agent:senseJar
----

The jar is then `spider-sense-agent/build/libs/spider-sense-{project-version}.jar`.
The `-launcher` jar beside it is a build artifact, not the jar to run.
Keep the jar's absolute path in a variable, because the commands in this manual use it:

[source,bash,subs="attributes+"]
----
SENSE="$PWD/spider-sense-agent/build/libs/spider-sense-{project-version}.jar"
----

`./gradlew publishToMavenLocal` puts the jar and the plugin, unsigned, into `~/.m2` at the same version.
A project with `mavenLocal()` in `repositories` and in `pluginManagement.repositories` then resolves them as it would a release.
This is how a build outside this repository uses an unreleased version.

[#quick-start]
== Quick start

[source,bash]
----
java -javaagent:"$SENSE" -Dotel.service.name=my-app -jar your-app.jar
----

Open http://localhost:4000[].
The collector and the UI run inside the application's JVM, and the first request appears a second or two after it is served.
Always set `-Dotel.service.name=`, because without it the service gets the OpenTelemetry agent's own default name, `unknown_service:java`.

`java -jar "$SENSE" status` checks the setup from a terminal.
It names the mode, the port, the database file, the thresholds in force, the services seen and how many spans are stored.

[#ways-to-run]
== The four ways to run it

[cols="1,2,2",options="header"]
|===
| Way | Command | Where it is described

| The jar on the command line
| `java -javaagent:spider-sense.jar -jar app.jar`
| xref:modes.adoc#agent[Agent mode], and xref:modes.adoc#forwarding[forwarding] when several applications share one UI

| The Gradle plugin
| `id 'net.benelog.spidersense' version '{project-version}'`, then `./gradlew bootRun`
| xref:gradle-plugin.adoc[The Gradle Plugin]

| Maven
| `mvn spring-boot:run -Dspring-boot.run.agents=/path/to/spider-sense.jar`
| xref:maven.adoc[Maven]

| Standalone
| `java -jar spider-sense.jar`
| xref:modes.adoc#standalone[Standalone mode], for anything that already speaks OTLP/HTTP, including a Java application under the stock OpenTelemetry Java agent
|===

`bootRun` and `spring-boot:run` fork the JVM themselves, so the agent has to be handed to the build tool rather than typed on your own command line.
The Gradle plugin and the Maven parameters exist to hand it over.

[#java-versions]
== Java versions

The jar itself needs Java 21 or later, which is Spider Silk's floor.
The monitored application can run on any JVM the OpenTelemetry Java agent supports, but the embedded UI needs 21 or later, so agent mode requires 21 or later.
An application on an older JVM can still be measured: run Spider Sense standalone on Java 21 or later and point the application at it, as xref:modes.adoc#forwarding[forwarding] describes.
